# 1.3 Global State Variables { #plasic-state-variables }

This note is a field guide to the global state of the PlaSiC C implementation. Nearly every
module in `src/` reads from or writes to the shared variables declared in
`src/state/plasicmod_state.h` and initialized in `src/state/plasicmod_state.c`. Knowing what
each name means, how it is shaped, and what it starts from is the fastest way to read any other
source file in the project. The state layout and default constants follow the PlaSim model
description (Fraedrich et al., 2005).

For every variable the tables below give:

- the **C identifier** used in the code;
- the **meaning** (physical quantity or role in the algorithm);
- the **default** written by `plasic_state_init()`.


## 1. Naming and Layout Conventions

Reading the code means decoding many flattened arrays; the naming scheme is systematic:

All 2-D fields are stored in **column-major** order with the horizontal index running fastest:

- grid-point field: element `(point, level)` is `array[point + level * PLASIC_NHOR]`;
- spectral field: coefficient `(mode, level)` is `array[mode + level * PLASIC_NRSP]` for the
  global arrays and `array[mode + level * PLASIC_NSPP]` for the local blocks;
- 3-D fields such as `plasic_bm1` append the wavenumber dimension last
  (`level + inner * NLEV + n * NLEV * NLEV`).

The compile-time dimensions come from the `-D` macros passed by `src/Makefile`:

| Macro | Derivation | Default | Meaning |
|---|---|---|---|
| `PLASIC_NLAT` | `NLAT` | 48 | number of Gaussian latitudes |
| `PLASIC_NLEV` | `NLEV` | 13 | number of atmospheric σ levels |
| `PLASIC_NPRO` | `NPRO` | 1 | number of MPI ranks (used when `MPI=1`) |
| `PLASIC_NLON` | `2 * NLAT` | 96 | number of longitudes |
| `PLASIC_NLPP` | `NLAT / NPRO` | 48 | latitudes owned by this rank |
| `PLASIC_NHOR` | `NLON * NLPP` | 4608 | horizontal points in this rank's strip |
| `PLASIC_NUGP` | `NLON * NLAT` | 9216 | global horizontal grid size |
| `PLASIC_NTRU` | `(NLON - 1) / 3` | 31 | spectral truncation (largest total wavenumber) |
| `PLASIC_NLEM` | `NLEV - 1` | 12 | one less than the number of levels |
| `PLASIC_NLEP` | `NLEV + 1` | 14 | levels plus the surface entry used by `d*` fields |
| `PLASIC_NLSQ` | `NLEV * NLEV` | 169 | size of a square vertical operator |
| `PLASIC_NTP1` | `NTRU + 1` | 32 | truncation plus one |
| `PLASIC_NRSP` | `(NTRU + 1) * (NTRU + 2)` | 1056 | number of real spectral coefficients (Re/Im stored as separate floats) |
| `PLASIC_NSPP` | `ceil(NRSP / NPRO)` | 1056 | spectral coefficient slots reserved by this rank |
| `PLASIC_NESP` | `NSPP * NPRO` | 1056 | padded global spectral size; exceeds `NRSP` only when `NPRO` does not divide `NRSP` |
| `PLASIC_Y10_PLANETARY_VORTICITY_FACTOR` | constant | 1.63299310207 | $\sqrt{8/3}$, the factor converting normalized $Y_{1,0}$ into $2\sin\phi$ |

## 2. Calendar and Integration Control

| Variable | Meaning | Default |
|---|---|---|
| `plasic_nstep` | total number of dynamical steps completed since the epoch (`nstep = 0 ≡` year 0, January 1, 00:00); the model clock stored in the restart and written to output | `0` |
| `plasic_calendar` | active calendar kind: `0` = Gregorian (365/366 days, proleptic), `1` = 12 × 30-day (360 days, no leap years); decided by `--calendar` on a cold start and by the restart file on a warm start, and always saved back into the restart | `0` |
| `plasic_mpstep` | physics parameterization interval in **minutes per step**; selected from the horizontal resolution | `0` (startup: 45 for `NLAT<=32`, 36 for `NLAT<=48`, else `30*64/NLAT`) |
| `plasic_ntspd` | number of dynamical steps per solar day, `round(solar_day)/(mpstep*60)`, rounded up to an even number | `0` (computed) |
| `plasic_ndatim[7]` | current model time: `[year, month, day, hour, minute, weekday (0–6), leap-year flag]` | `-1` for every entry; filled by `step2cal(plasic_calendar, plasic_nstep, ...)` |
| `plasic_nafter` | accumulation window in steps; the output accumulators are reset every `nafter` steps | `0` (startup: `ntspd`, i.e. once per day) |
| `plasic_nkits` | number of startup short steps; while `> 0` the Robert–Asselin filter is not applied in the standard way; `0` means normal leapfrog integration | `3` (startup: `0`) |
| `plasic_nrad` | radiation switch: `1` enabled, `0` disabled | `1` |
| `plasic_nadv` | advection switch: `1` enabled, `0` disabled | `1` |
| `plasic_neqsig` | σ-level mode: `1` equidistant levels, `0` default stretched levels, `-1` use the configured `plasic_sigmah_configured` interfaces | `0` |
| `plasic_naccuout` | number of samples accumulated in the current output window; accumulators are divided by it to form time means | `0` |
| `plasic_nhdiff` | critical total wavenumber for scale-selective horizontal diffusion; modes below it are undamped | `15` |
| `plasic_ndheat` | switch for heating due to momentum dissipation (frictional heating): `1` enabled | `1` |
| `plasic_nsponge` | top-of-model sponge-layer switch: `1` enabled | `0` |

The start date itself is not a persistent global: a cold start turns
`--start-year/--start-yday/--start-hour/--start-minute` into `plasic_nstep` with `cal2step()`,
while a warm start reads `nstep` and `calendar` from the restart file. Calendar arithmetic
(month lengths, year lengths, leap years, step ↔ date conversion) lives only in
`src/tools/calmod_kernels.c`; see
[5.1 Calendar](../5-time-control/5.1-calendar.md).

| `plasic_tfrc` | Rayleigh friction time scale per level (**days**); with `NLEV == 10`, levels 0 and 1 default to 20 and 100 days | `0` |
| `plasic_tdissd` | divergence spectral-diffusion time scale (**days**) | `0.20` |
| `plasic_tdissz` | vorticity spectral-diffusion time scale (days) | `1.10` |
| `plasic_tdisst` | temperature spectral-diffusion time scale (days) | `5.60` |
| `plasic_tdissq` | humidity spectral-diffusion time scale (days) | `0.1` |

## 10. Where the Values Come From

To avoid confusion when comparing this page with a running model, recall the initialization
order from [1.2 Pseudocode for one time step](1.2-pseudocode-for-one-time-step.md):

1. `plasic_state_init()` writes the defaults listed above;
2. `runtime_initialize_dynamics()` calls `planet_defaults()`, derives the time scales
   (`deltsec`, `delt`, `ww`, `cv`, `ct`, ...), builds the σ grid, the dissipation rates, the
   reference profiles, and the semi-implicit matrices;
3. `runtime_load_atmosphere_restart()` either restores the state arrays from a restart file or
   builds a cold start from the surface data (orography, land mask, albedo, roughness, ...);
4. `plasic_physics_initialize()` fills the land, ocean, sea-ice, and radiation state and
   overwrites fields such as `plasic_dls`, `plasic_dwmax`, and `plasic_dglac` with the values
   read from the NetCDF surface data (every field of that data set is mapped in
   [6.5 Cold-Start Surface Boundary Fields at T42](../6-experiments/6.5-cold-start-surface-fields-t42.md)).

After step 4, the values in the tables above are the actual state used by the first time step;
the state defaults only matter where a restart file or a data file does not override them.
